# 물리 계수 (v2.2)

목표는 **게임이 그리는 흰 안내선과 같은 방향**으로 계산하는 것입니다. 사용자는 그 안내선을 보고 조준을 맞추기 때문입니다.
계수 값은 `billiard_solver/calibration.py` 한 곳에 있습니다.

## v2.1 → v2.2에서 되돌린 이유

v2.1에서는 플레이 영상의 공 움직임을 추적해서 물리값을 바꿨습니다.
쿠션 반사는 더 넓게(tan비 1.26), 공에 맞은 뒤 수구는 더 앞으로(0.55) 가게 했습니다.
그런데 실제 게임에서 써 보니 **게임 안내선과 추천 경로가 크게 어긋났습니다.**
- 쿠션 반사: 게임 안내선 ≈ 0.9, v2.1 ≈ 1.33
- 공 맞은 뒤: 게임 안내선 = 거의 접선, v2.1은 거의 직진

영상값은 천천히 구르는 목적구 등 조건이 다른 데이터라 첫 충돌에 그대로 쓰면 안 됐습니다.
v2.2는 방향 값을 게임 안내선 기준(v2.0 값)으로 되돌렸습니다.

## 계수 표

| 계수 | 값 | 상태 | 근거 |
|---|---|---|---|
| 쿠션 반사 비율 (입사각별) | 0~45° 0.85, 55° 0.93, 65° 1.00, 75° 1.02 | 안내선 | 영상에서 흰 안내선 105개 장면(샷 약 50개) 구간별 중앙값 |
| 공 맞은 뒤 수구 `follow` | 0 (접선) | 안내선 | 게임 안내선 읽기 0.02 |
| 쿠션 충돌선 `cushion_offset` | 0.18r | 안내선 | 링이 쿠션에 닿는 위치 |
| 감속 `decel`, 힘 100% 속도 `v0_max` | 1.0, 4.2 | 맞춤 (v2.0) | 힘은 예상치 |
| 목적구 속도 `obj_transfer`, `ball_loss` | 0.97, 0.97 | 맞춤 / 미확정 | |
| 힘 곡선 `power_exponent` | 1.0 | 미확정 | |
| 상하 당점 `top_k` | 0.6 | 미확정 | 스핀은 무스핀으로 안 될 때만 씀 |
| 좌우 당점 `side_k`, `side_decay` | 0.22, 0.6 | 미확정 | 방향만 확인 |
| 당점 최대 | 2팁 원 | 가정 | 게임 당점 화면 초록 원 |

F5는 화면의 흰 안내선을 직접 읽어서 첫 충돌 뒤 방향을 그대로 씁니다. 그래서 F5 경로는 계수와 상관없이 안내선과 일치합니다.

## 참고: v2.1 영상 측정 (지금은 안 씀)

60fps 영상 15,148프레임을 추적해서 잰 값입니다. 목적구 쿠션 반발 0.61, 구르는 감속이 매우 작음, 친 직후 미끄럼 손실 약 30%.
게임 안내선과 다르게 나와서 계산에는 쓰지 않습니다.
당점 세기를 재려면 같은 자리에서 당점만 바꿔 친 대조 영상이 필요합니다.
